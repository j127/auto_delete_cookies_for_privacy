# Firefox manual test matrix

The gate for every Firefox (AMO) release, first written as the merge gate for the Firefox port (issue #290): run every row once per browser channel on a real, headed Firefox before the release, record the outcome in the Result columns, and file a follow-up issue for every failure (reference it in the row). Automated coverage notes say what the unit/regression suites already pin so the manual pass can focus on what only a real browser shows.

Automated companion: `just e2e_firefox` drives a real headless Firefox through rows 1–12 and 14–22 (and the row-13 plumbing), plus the Support page's system details and bug-report email (#435, #436), with a privileged extension-page probe and chrome-context script — run it before starting a manual pass; the rows it covers then only need spot-checking, and each row's Automated coverage cell names what stays manual (the popup and right-click keeps of rows 7, 8 and 11, the Allow click of row 15, the restart parts of rows 6 and 10, and a mail app actually opening for the email link). It uses the default Firefox install; `FIREFOX_BIN=/path/to/firefox` points it at another channel, such as the ESR, so run it once per channel. CI's `e2e-firefox` job runs it on both channels for every pull request, one pinned version each (the job's matrix in `.github/workflows/ci.yml`), so a green CI run already covers the automated rows of both columns at those versions. On macOS 27, a Firefox that geckodriver starts as its own child from a terminal inside another app (such as an editor's or a coding app's terminal pane) is refused its own app-data folder (#465), and session creation fails with `Process (pid=...) unexpectedly closed with status 1`. So on macOS, when `FIREFOX_BIN` is not set, `just e2e_firefox` and `just store_screenshots_firefox` set it to `scripts/firefox_via_open.sh`, which starts Firefox through `open` and answers geckodriver's `--version` probe with the installed Firefox's real version (#465); nothing to configure, and it works from Terminal.app too. It launches `/Applications/Firefox.app`, so to test another channel such as the ESR on macOS, run that build's binary directly with `FIREFOX_BIN` from Terminal.app, or rely on CI. The first launch after a failed attempt sometimes exits at once; the wrapper retries once when Firefox quits within 3 seconds. A failed attempt can also leave a Firefox with a `rust_mozprofile` profile running; `pkill -f rust_mozprofile` clears it. Setup for every session: `just build_firefox`, then either `just run_firefox` (throwaway profile; on macOS it starts Firefox through `open`, via `scripts/firefox_via_open.sh`, to avoid that same block (#465); `bunx web-ext run --source-dir builds/firefox --firefox /path/to/firefox` picks the channel) or `about:debugging#/runtime/this-firefox` → "Load Temporary Add-on" → any file inside `builds/firefox/`. Use a test site that sets cookies + localStorage (e.g. an httpbin cookie page plus any site with a consent banner), and keep the extension's Debug Mode on so the background console narrates decisions.

Chromium companion: `just e2e_chromium` ([testing-chromium.md](testing-chromium.md)), run by CI's `e2e-chromium` job, checks on Chrome for Testing the storage end state that rows 13 and 21 can only check through the cleanup log on Gecko.

Channels: **ESR** = the oldest Firefox ESR that Mozilla still updates and the manifest still supports (`FIREFOX_STRICT_MIN_VERSION` in `scripts/firefox_manifest.ts`), which is ESR 140 as of September 2026. `FIREFOX_ESR` in Mozilla's product details (https://product-details.mozilla.org/1.0/firefox_versions.json) names the current one. **Rel** = the current Firefox release. Both labels stay generic because both channels move; each run records the exact versions under Runs.

## Firefox for Android

The same Firefox package runs on Firefox for Android 142 or newer (`FIREFOX_ANDROID_STRICT_MIN_VERSION` in `scripts/firefox_manifest.ts`), and on rebuilds of it such as Fennec F-Droid (#534). The matrix above is desktop-only. Before AMO's "Firefox for Android" compatibility box is ticked for a version (docs/store/firefox/runbook.md, step 2), run the checks below once on a phone or emulator and record them under Runs with the Firefox for Android version.

What differs on Android, and what the code does about it:

- No `contextualIdentities`, `contextMenus` or `windows` API. `hasContainerApi` and `hasContextMenuApi` (`src/services/browser-capabilities.ts`) hide the container settings and the context menu setting, and the Private keep list is erased through tabs instead of windows (#537): `src/services/private-window-events.ts` caches the open private tabs in `storage.session` (`tabs.onRemoved` carries no `incognito` flag) and erases the list when the last private tab closes, or at the first background start of a browser session that lists no private tab (Firefox for Android never restores private tabs). Saved sites says so in `privateListErasedAndroidText`.
- MDN lists `tabs.Tab.cookieStoreId` as unsupported, but Gecko's Android tabs code sets it. In case a tab comes without one, `tabCookieStoreId` keys it `firefox-default` / `firefox-private` rather than Chrome's `0` / `1`.
- `tabs.query` lists only the tabs Firefox has loaded since it started (Mozilla bug 1583281). `src/services/carried-open-tabs.ts` carries the sites that were open over a restart and treats them as open tabs until a listed tab shows them or the person cleans including open tabs. Trade-off: a tab closed from the tab tray without being opened again keeps its site's cookies until then.
- The popup opens as a full-width page; its 430px minimum width is capped at the screen width.

Setup: an emulator from Android Studio's Device Manager (any recent Pixel image) or a phone with USB debugging, `adb` from the Android SDK platform-tools, and Firefox for Android from the Play Store or from https://archive.mozilla.org/pub/fenix/releases/ (`adb install` the APK for the device's ABI). In Firefox: Settings → "Remote debugging via USB" on. Then run the command below (`ADB_BIN=~/Library/Android/sdk/platform-tools/adb` when adb is not on PATH, `ADB_DEVICE=emulator-5554` with several devices attached, `FIREFOX_APK=org.mozilla.fennec_fdroid` for Fennec F-Droid). web-ext installs the build as a temporary add-on and prints its console messages; `about:debugging` on a desktop Firefox can inspect the background page over the same adb connection.

Things that cost time on the first run (2026-10-20): give the emulator 4 GB of RAM or more and software GPU rendering (`emulator -avd <name> -memory 6144 -gpu swiftshader_indirect`; the default 2 GB Play Store image thrashes, and the default GPU mode crashed the emulator repeatedly), and keep its screen on (`adb shell svc power stayon true`), because web-ext stalls at "Stopping existing instances" while the screen is asleep. A temporary add-on is gone after Firefox restarts, so for A5 run the recipe again after the restart; its `storage.local` survives the reinstall. Firefox blocks screenshots of private tabs. Long `adb shell input text` strings drop characters; open pages from the extension (`browser.tabs.create`) or type short addresses.

More from the second run (2026-10-22): the emulator needs a quiet host. With the Mac's load average above about 100 (other builds or CI jobs running), Android's watchdog kept killing `system_server` and Firefox died with it, on the Play Store image and on a lighter one alike; wait until the 15-minute load stays low before starting. An Android 14 "Google APIs" image (no Play Store) booted in under a minute and stayed stable once the host was quiet. If web-ext times out waiting for the debugger socket, the screen is usually off or locked (`adb shell input keyevent KEYCODE_WAKEUP`); `WEB_EXT_ADB_DISCOVERY_TIMEOUT=300000` gives a slow device longer. `adb shell settings put global hide_error_dialogs 1` keeps "isn't responding" dialogs from covering the screen. After a private tab has been in use, tabs the extension opens (including its settings page) open as private tabs too, so switch back to a normal tab from the tab tray before A7's setup.

mise exec -- just run_firefox_android
